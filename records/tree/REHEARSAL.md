# REHEARSAL DATA — DO NOT POINT A ROUTER AT THIS TREE

Everything under `records/tree/` was produced by a **test**, not by a release:

* `keys/tollgate-testing.pem` is a **throwaway public key**. Its private half
  was created inside the test's temporary work directory and deleted with it, so
  this key can never sign anything again. It exists here only so the committed
  snapshot is a complete, inspectable tree.
* `testing/25.12/aarch64_cortex-a53/packages.adb` is a **signed sample index**
  for the real `tollgate-wrt-0.6.0_alpha1-r1.apk` (sha256 `4e0f8654…`), signed
  by that throwaway key. Its own sha256 changes on every run — ECDSA signatures
  are randomised — so it is not "the" index for that version.
* `manifest.sha256` is the build manifest the sample references.

Reproduce it (any host, no Caddy, no VPS, no docker):

```sh
scripts/get-host-apk-tools.sh --out .feed-tools/apk
tests/feed-https-publish-test.sh --artifacts ~/sdk-run/mediatek-filogic/out \
  --arch aarch64_cortex-a53 --apk-bin .feed-tools/apk/bin/apk
```

The **live** `prod`/`testing` trees are generated by the publish job (or by hand
per `docs/feed-index-publishing.md`) into a durable tree directory with the real
channel keys, and are published from there. Nothing in this directory is served
to anyone.
